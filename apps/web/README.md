# Web Application

Teacher-facing front end for Sprint 001: the **Educational Case Notebook**.

We build exactly **three pages**. Nothing more.

## Page 1 — Students

- Search a student.
- Click a student.
- Done.

No list management. No profiles dashboard. Just find the child and open them.

## Page 2 — Learning Cases

Every **active struggle** for that student.

- Not report cards.
- Not marks.
- Cases.

Each case is a live struggle being worked through, grounded in the domain
(Student → Learning Case → Observation → Root Gap → Intervention → Review →
Close Case).

## Page 3 — New Observation

Five fields only:

1. **Observed** — what you saw.
2. **Possible Root Gap** — the earliest missing prerequisite (use the LDG).
3. **Evidence** — what justifies this.
4. **Strategy** — the intervention you chose.
5. **Next Review** — when you'll look again.

Done.

## Explicitly NOT built

- **No Dashboard.** Dashboards are consumers of data. We don't even have data
  yet. Delete it from your mind.
- **No Analytics.** We have no evidence.
- **No AI.** We have no validated reasoning.
- **No Recommendation Engine.** You — the teacher — are still the recommendation
  engine.

See `.ai/anti-patterns.md`, `.ai/constraints.md`, and the root `README.md`.
