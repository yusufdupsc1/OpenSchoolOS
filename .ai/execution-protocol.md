# OpenSchoolOS Execution Protocol

## Mission

Execute the project autonomously while preserving the Project Constitution.

The objective is NOT to maximize code.

The objective is to maximize educational value through small, production-quality increments.

---

# Execution Loop

Repeat this loop forever until Sprint completion.

STEP 1 — Synchronize

Read:

- .ai/
- docs/
- knowledge/
- roadmap
- active sprint

Understand the current state.

Never assume.

---

STEP 2 — Review

Review everything implemented since the previous milestone.

Run:

- Architecture Review
- DDD Review
- Code Quality Review
- Repository Health Review

If problems exist,

fix them first.

Never build on unstable foundations.

---

STEP 3 — Plan

Determine the smallest remaining milestone.

Requirements:

- less than 2 hours
- independently testable
- independently reviewable
- independently commit-able

Never plan more than one milestone ahead.

---

STEP 4 — Implement

Implement only the approved milestone.

Follow:

Educational Problem

↓

Teacher Workflow

↓

Domain

↓

Business Rules

↓

Infrastructure

↓

API

↓

UI

↓

Tests

Never skip this order.

---

STEP 5 — Self Review

Review the implementation like a senior reviewer.

Check:

- DDD
- Clean Architecture
- Naming
- Complexity
- Duplication
- Maintainability
- Educational correctness

Fix critical issues.

---

STEP 6 — Test

Run every available test.

If tests fail,

fix them.

Repeat until green.

---

STEP 7 — Repository Audit

Verify:

- no dead code
- no duplicated code
- no architecture drift
- no dependency violations
- no documentation drift

---

STEP 8 — Commit Report

Return ONLY:

Completed

Files changed

Tests executed

Architecture review

Known limitations

Suggested commit message

Definition of Done

Then STOP.

Wait for the Founder.

---

# Founder Commands

If Founder writes:

Next

↓

Execute the next milestone.

---

Go Ahead

↓

Continue from the current milestone.

---

Review

↓

Perform engineering review only.

---

Refactor

↓

Improve existing implementation only.

---

Sync

↓

Synchronize the repository.

---

Release

↓

Prepare release.

---

Research

↓

Pause implementation.

Enter research mode.

---

# Stop Conditions

Immediately stop if:

Technology Stack changes

Architecture changes

Educational Philosophy changes

Repository Constitution changes

Security issue discovered

Data integrity risk

Breaking change

Ask the Founder before proceeding.

---

# Golden Rule

Never ask:

"What should I do next?"

Instead determine the next milestone yourself.

Only interrupt when:

- blocked
- ambiguity exists
- constitutional conflict exists
- founder decision required

Otherwise continue autonomously.
