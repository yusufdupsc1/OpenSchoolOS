# Project Thesis

Answer only four questions.

## 1. What educational problem are we solving?

Teachers accumulate observations about a struggling learner but have no simple,
private place to turn that observation into a reasoned diagnosis and a chosen
intervention — and to revisit it later. Decisions get made on intuition alone,
without a visible chain of evidence.

## 2. Why do existing school systems fail to solve it?

They are School Management Systems: attendance, marks, ERP, reporting. They
optimise administration, not the teacher's educational reasoning. They add
dashboards and analytics instead of supporting one careful case at a time.

## 3. What is our unique hypothesis?

If we give one teacher a minimal **Educational Case Notebook** —
Student → Learning Case → Observation → Root Gap → Intervention → Review →
Close Case — grounded in the Learning Dependency Graph, teacher reasoning
improves measurably. Pedagogy drives software; software never drives pedagogy.

## 4. How will we know we're right?

If Yusuf's teaching changes for the better over one month using the Notebook for
one learner, we have earned the right to build more. Until then, we do not
scale.

Beyond that, the real test is the repository itself. Our GitHub goal is not
stars or forks — it is for a visitor to say: "This teacher deeply understands
learning." If the repo does not earn that, the metrics do not matter.
